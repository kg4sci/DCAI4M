# 打分准则（中文版本，译自 x.md 与 y.md）

权威来源：项目根目录的 `x.md`（X 轴）与 `y.md`（Y 轴）。本文件是精简的常备参考，如有疑问请回读原始文件。

---

## X 轴：任务智能度（Task Intelligence）

六个维度，每个维度为 0–4 的整数分。

| 符号 | 维度 | 权重 |
|---|---|---:|
| O | 输出与决策角色（Output and Decision Role） | 25% |
| A | 自适应性与序贯性（Adaptivity and Sequentiality） | 20% |
| I | 工作流整合度（Workflow Integration） | 20% |
| G | 目标与约束处理（Goal and Constraint Handling） | 15% |
| U | 不确定性与失败处理（Uncertainty and Failure Handling） | 10% |
| P | 自主性与可执行性（Autonomy and Actionability） | 10% |

### 各维度评分锚点

#### O —— 输出与决策角色

| 分值 | 标准 |
|---:|---|
| 0 | 无实质性机器学习任务；仅数据处理或规则化处理。 |
| 1 | 单一性质或单一标签预测。 |
| 2 | 多性质预测、候选排序或风险评估。 |
| 3 | 候选生成、逆向设计或目标导向设计。 |
| 4 | 对下一步候选、实验、资源分配或发现策略做出决策。 |

#### A —— 自适应性与序贯性

| 分值 | 标准 |
|---:|---|
| 0 | 完全静态、一次性预测。 |
| 1 | 条件式预测或生成，但不根据新结果更新行为。 |
| 2 | 一次性主动筛选。 |
| 3 | 利用仿真或离线反馈进行多轮序贯优化。 |
| 4 | 多轮、反馈驱动的自适应闭环。 |

#### I —— 工作流整合度

| 分值 | 标准 |
|---:|---|
| 0 | 无机器学习工作流。 |
| 1 | 单一模型完成单一任务。 |
| 2 | 单一任务的增强版本。 |
| 3 | 多个模型或模块按顺序连接。 |
| 4 | 连接多个环节（生成、预测、筛选、实验规划、反馈更新）的一体化发现系统。 |

#### G —— 目标与约束处理

| 分值 | 标准 |
|---:|---|
| 0 | 无显式优化目标或约束。 |
| 1 | 单一优化目标。 |
| 2 | 单一目标加静态约束。 |
| 3 | 多目标或多约束优化。 |
| 4 | 动态、多目标、含资源约束的决策。 |

#### U —— 不确定性与失败处理

| 分值 | 标准 |
|---:|---|
| 0 | 仅输出确定性结果。 |
| 1 | 报告了基础不确定性，但不影响策略。 |
| 2 | 不确定性被用于候选筛选。 |
| 3 | 显式处理噪声、失败与阴性结果。 |
| 4 | 不确定性驱动风险感知的搜索策略。 |

#### P —— 自主性与可执行性

| 分值 | 标准 |
|---:|---|
| 0 | 仅输出预测结果。 |
| 1 | 给出建议，行动规则由人类决定。 |
| 2 | 自动执行固定工作流。 |
| 3 | 根据反馈自动选择下一步动作。 |
| 4 | 自主规划、执行、监控并纠正整个过程。 |

### 聚合计算

```
X100 = 100 * [0.25*(O/4) + 0.20*(A/4) + 0.20*(I/4) + 0.15*(G/4) + 0.10*(U/4) + 0.10*(P/4)]
     = 6.25*O + 5*A + 5*I + 3.75*G + 2.5*U + 2.5*P
X5   = X100 / 20
```

### 强制封顶规则（Mandatory Caps）

**打分阶段的限制**（在聚合之前，通过下调维度原始分执行）：

- **Cap 4.** 若并未真正实现并执行任何智能体或闭环流程，则 `P <= 1` 且 `A <= 1`。
- **Cap 5.** 若生成模型仅以有效性/新颖性/多样性评估，没有目标性质、约束、筛选或下游决策，则 `O <= 2`。
- **Cap 6.** 若论文声称有反馈但从未证明后续决策依赖早期结果，不得给 `A = 3` 或 `A = 4`。

**聚合后的封顶**（由 `compute_scores.py` 执行；多条同时触发时取最严格的一条）：

- **Cap 1.** 若 `O < 4`，最终 `X5 <= 2.5`。
- **Cap 2.** 若 `A < 3`，最终 `X5 <= 3.0`。
- **Cap 3.** 若 `I < 3`，最终 `X5 <= 3.0`。
- **Cap 5（数值版）.** 当 Cap 5 在打分阶段触发时，额外施加 `X5 <= 2.5`。

### 等级划分

| 最终 X5 | 等级 | 名称 |
|---|---:|---|
| 0 <= X5 < 0.5 | 0 | 数据级（Data-level） |
| 0.5 <= X5 < 1.5 | 1 | 预测级（Predictive） |
| 1.5 <= X5 < 2.5 | 2 | 设计导向级（Design-oriented） |
| 2.5 <= X5 < 3.75 | 3 | 决策导向级（Decision-oriented） |
| 3.75 <= X5 < 4.6 | 4 | 自适应发现级（Adaptive discovery） |
| 4.6 <= X5 <= 5.0 | 5 | 自主发现级（Autonomous discovery） |

**Level 5 附加门槛：** 必须满足 `O = 4 且 A >= 3 且 I = 4 且 P >= 3`。若未通过，降为 Level 4，并在 `applied_caps` 中记录 `"Level 5 gate failed -> demoted to 4"`。

### 证据与置信度

每个 X 维度都需记录：

- `text`：来自该行内容的简短引文或转述，用于支持所打分值；若无依据则填字符串 `"not reported"`。
- `confidence`：`high`（明确确立）、`medium`（有支持但不完整）、`low`（依据有限或含糊，分数取保守值）。

## Y 轴：实验导向度（Experimental Orientation）

三个维度，每个 0–2 分。采用粗粒度 0–2 量表是有意为之：以降低文献综述中的主观判断负担。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| **E —— 对实验结果的依赖** | 无真实实验结果；评估仅使用仿真或代理标签。 | 实验结果用于训练、校准或少数示例案例，但不构成正式的实验测试。 | 真实实验结果作为测试的正式依据；可以在实验数据上单独评估性能。 |
| **R —— 与实验需求的对齐** | 数据仅提供理想化性质或代理标签，与具体实验用途无关联。 | 数据明确针对某一实验需求，但未覆盖满足该需求所需的关键约束。 | 数据与候选范围支持一个明确定义的实验决策，并包含相关目标与关键约束（或通过设计保证）。 |
| **C —— 关键实验条件的完备性** | 仅提供材料标识与结果，缺少解读结果所需的条件。 | 提供了部分关键条件，但缺失会影响解读或对比。 | 提供了任务所需的关键制备、加工与测量条件，且可追溯到具体样品或标准化协议。 |

### E —— 判定顺序

1. 是否使用了实验结果？若否，`E = 0`。
2. 是否仅用于训练、校准或少数成功案例？若是，`E = 1`。
3. 是否存在定义明确的实验测试集或预先设定的实验评估，并单独报告？若是，`E = 2`。

注记：

- 来自文献或数据库的历史实验测量值同样算作真实实验结果，基准作者无需亲自补做实验。
- 仿真训练 + 实验测试可以达到 `E = 2`；实验训练 + 仿真测试通常只给 `E = 1`。
- 对混合测试集，若只报告了汇总指标、无法拆分出实验子集，不得给 `E = 2`。

### R —— 两个固定问题

1. 数据所代表的目标是否对应一个明确定义的实验用途？
2. 数据或候选范围是否包含该用途所需的关键约束？

- 两问均不满足 → `R = 0`。
- 仅满足 (1) → `R = 1`。
- 两者均满足 → `R = 2`。
- 信息不足 → 标记 `NR`，不要猜测。

关键约束由基准**声明的预期用途**决定，而非穷举清单。多个性质或闭环操作不会自动额外加分。

### C —— 按任务预定义的关键条件

通常需要检查的关键条件示例：

| 任务或性质 | 关键条件示例 |
|---|---|
| 电池性能 | 倍率（C-rate）、电压窗口、温度、影响目标指标的电极信息。 |
| 催化性能 | 温度、压力或电势、反应体系、归一化方法。 |
| 力学性能 | 加工/热处理状态、测试温度、加载方式或应变速率。 |
| 合成条件推荐 | 前驱体、配比、温度、时间、气氛或溶剂。 |

由标准化协议固定的条件视为已提供。若大量记录缺少关键条件，不得因少数案例完整就给 `C = 2`。

### 避免 R 与 C 双重扣分

- **R** 问的是：数据是否代表了要解决的实际问题。
- **C** 问的是：所报告结果的实验上下文是否被记录在案。

同一数据集可以在 R 上高分、C 上低分，反之亦然。

### 聚合计算

```
S = E + R + C   （取值范围 0–6）
```

- 主要结果应报告三个分量分数；总分只是次要信息。
- 若任一维度为 `NR`，不计算 `S`（保留 `null`）；脚本会设置 `y_complete = false`。
- 当某维度确实不适用时允许记 `NA`（例如纯仿真基准，`E = 0` 而 `C = NA`）。
- 有维度为 `NR` 或 `NA` 时，不得对其余维度重新归一化——这会破坏可比性。

该总分是**数据的实验导向度得分**，不是基准的整体质量评分。

## 全局评估原则（译自 x.md 第 2 节）

1. 只使用显式证据。
2. 避免按术语（而非实际行为）打分。
3. 不假设未报告的能力。
4. 每个分数都要给出理由，或注明 "not reported"（未报告）。
5. 区分"声称"与"演示"。
6. 评估任务与行为，而非模型规模或精度。
7. 高级别系统要求真正完成集成。
8. 判定为自适应闭环要求有反馈的证据。
